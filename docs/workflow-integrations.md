# Playground, forms and service workflows

The playground covers fourteen public components. Component options, feedback
states, drawer side, initial focus, dates, selected disciplines, table options,
width and theme are serialised into a validated query string. Copy configuration
link reproduces the selected configuration. Unknown values are ignored; numeric
values are bounded and date-only values use local calendar fields. Draft note
text and edited table records remain local sample state.

The copy panel provides a complete client-component example. Loading and error
states are deliberate examples; wire retry and persistence to your service.
Keyboard guidance explains focus, selection, dismissal and cell editing. Complete
prop tables are generated by scripts/prepare-api.mjs for every component page,
including related types and expandable forwarded React/HTML props. Public function
defaults come from the source; a dash means no default at that boundary.

## Inline editing

Select the displayed value, or focus it and press Enter or F2, to begin editing.
Use non-interactive display content. Full-project editing is in the row action menu.

EditableCell accepts text/date values or a list of select options, a validation
callback and an abortable async save callback. It keeps the draft on errors,
prevents duplicate saves and restores focus after save/cancel. It snapshots
originalValue and optional revision at edit start. The application uses that
revision for an optimistic concurrency check; a refreshed row must not silently
replace the draft's original version. The host owns committed data and focus when
a successful edit removes a row from the current filter.

Outline uses this component for names, dates and statuses. Saves refresh the
current query without replacing every row with a loading skeleton. Stale query
results are rejected. Validation errors return to the edited field; service and
version errors preserve the input. Modal editing remains available for full
project details.

## React Hook Form

React Hook Form 7.90.0 is an optional peer. Import RHFField and RHFControl from
@bld8/ui/react-hook-form or the installed registry module. RHFField wraps native
inputs with labels/errors; RHFControl maps value/onValueChange, onBlur, inputRef
and error to controls that own their label. Standard Controller and register
continue to work. Define explicit null/array/string defaults and pass the host
form's control and rules. Input/Select/MultiSelect/date ref bindings reach the
actual input or trigger so setFocus can target invalid controls.

The working project form maps HTTP validation failures with setError, preserves
values after rejected saves and restores server-error focus after pending inputs
are enabled. It does not introduce a required form framework into the core UI
entry point. The downloadable form starter includes the same client and sample API.

## HTTP adapter

createOutlineHttpRepository accepts baseUrl, optional fetch, per-request headers
(or an async header function) and credentials (same-origin by default). It sends
signals, validates successful response shapes, maps 422 field errors and preserves
HTTP status on other failures. The host application owns sessions and authentication.

The contract is documented at /integrations/outline-http. The reference server
in examples/outline-http/demo-api.ts handles filtering/paging, validation, writes,
record versions and bulk updates. The sample session header scopes temporary
process-local data; it is not authentication. Sessions are bounded and expire
following inactivity or server restart. A real service needs authenticated
ownership and atomic database version checks. No user files are uploaded.

The two extra ZIP starters contain runnable Next.js API routes and local BLD8
packages. Source is allowlisted, and the optional form starter declares its
React Hook Form dependency. Registry installation supports the adapter and form
bindings; server integration is supplied through the reference starter.
